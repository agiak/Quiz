# Κουίζ για ομάδες — Προδιαγραφή σχεδιασμού

Ημερομηνία: 2026-11-02 · Κατάσταση: προς έγκριση

## 1. Σκοπός

Ένα online τηλεπαιχνίδι γνώσεων που παίζουν πολλές ομάδες ταυτόχρονα. Ένας παρουσιαστής
δείχνει τις ερωτήσεις σε κεντρική οθόνη (προβολέας ή τηλεόραση) και ο αρχηγός κάθε ομάδας
απαντά από το κινητό του. Όλες οι ομάδες απαντούν σε όλες τις ερωτήσεις και καμία δεν
αποκλείεται. Στο τέλος ο παρουσιαστής αποκαλύπτει πρώτα τις σωστές απαντήσεις και μετά την
κατάταξη.

**Επιτυχία σημαίνει:** ο παρουσιαστής ανοίγει παιχνίδι από ένα κουίζ που έφτιαξε, οι αρχηγοί
μπαίνουν με κωδικό ή QR code μέσα σε λίγα δευτερόλεπτα, το παιχνίδι ολοκληρώνεται χωρίς να
χαθεί καμία απάντηση (ακόμα και με αποσυνδέσεις), και η κατάταξη είναι σωστή.

## 2. Αποφάσεις

| Θέμα | Απόφαση |
|---|---|
| Σύνδεση αρχηγών | Εξαψήφιος κωδικός παιχνιδιού + QR code που ανοίγει `/play?code=…`. Ο αρχηγός γράφει το όνομα της ομάδας. |
| Επανασύνδεση | Μυστικό token ανά ομάδα στο `localStorage` του κινητού. Η ομάδα επιστρέφει αυτόματα στην ίδια κατάσταση. |
| Ερωτήσεις | Τις γράφει ο διαχειριστής από τη σελίδα διαχείρισης. Αποθηκεύονται στη βάση. |
| Τύπος ερώτησης | Πολλαπλής επιλογής, 2 έως 4 επιλογές, μία σωστή. Μόνο κείμενο. |
| Βαθμολογία | 1 πόντος ανά σωστή απάντηση. Καμία βοήθεια, κανένα μπόνους ταχύτητας. |
| Χρονόμετρο | Χρόνος ανά κουίζ (5–300″, προεπιλογή 30″), με προαιρετικό δικό της χρόνο ανά ερώτηση. |
| Αλλαγή απάντησης | Επιτρέπεται όσες φορές θέλει ο αρχηγός μέχρι τη λήξη του χρόνου. Μετράει η τελευταία. |
| Κλείσιμο ερώτησης | Όταν λήξει ο χρόνος, ή νωρίτερα με το κουμπί «Κλείσιμο τώρα» του παρουσιαστή. Ποτέ αυτόματα επειδή απάντησαν όλοι. |
| Ρυθμός | Ο παρουσιαστής πατά «Έναρξη» / «Επόμενη». |
| Κατά τη διάρκεια | Καμία ομάδα δεν μαθαίνει αν απάντησε σωστά. Η κεντρική οθόνη δείχνει μόνο «Απάντησαν Χ από Υ». Καμία κατάταξη. |
| Αποτελέσματα | Πρώτα οι σωστές απαντήσεις (μόνο ερώτηση + σωστή απάντηση, χωρίς στατιστικά ή απαντήσεις ομάδων), μετά η κατάταξη από την τελευταία θέση προς την πρώτη. |
| Κινητά στα αποτελέσματα | Κλειδωμένα με «Κοιτάξτε την κεντρική οθόνη» μέχρι να εμφανιστεί η 1η θέση. Μετά: η κατάταξη και μόνο οι απαντήσεις της δικής τους ομάδας. |
| Ισοβαθμίες | Κοινή θέση (1, 1, 3). Μέσα στην ίδια θέση, αλφαβητική σειρά. |
| Αργοπορημένες ομάδες | Μπαίνουν όσο το παιχνίδι δεν έχει φτάσει στα αποτελέσματα. Παίρνουν 0 στις ερωτήσεις που έχασαν. |
| Διαχείριση | Ένας διαχειριστής με έναν κωδικό πρόσβασης. |
| Υποδομή | Frontend στο Vercel, backend στο Render, βάση Postgres στο Neon. |

## 3. Αρχιτεκτονική

```
 Κινητά αρχηγών ─┐                                          
 Οθόνη παρουσ.  ─┼─ Vercel: web (React) ──HTTPS/WebSocket── Render: server (Node + Socket.IO) ── Neon Postgres
 Διαχείριση     ─┘
```

Ένα αποθετήριο GitHub, TypeScript παντού:

- `web/`: React + Vite + React Router + `socket.io-client`. Στατική εφαρμογή στο Vercel.
- `server/`: Node.js + Express + Socket.IO + `pg`. Web service στο Render.
- `shared/`: οι τύποι του πρωτοκόλλου (μηνύματα socket, σχήματα δεδομένων), κοινοί για web και server.

Ο server είναι η μόνη πηγή αλήθειας: κρατά το ρολόι, αποφασίζει πότε κλείνει μια ερώτηση,
βαθμολογεί και αποφασίζει τι βλέπει κάθε ρόλος. Οι σωστές απαντήσεις δεν στέλνονται ποτέ σε
κινητό πριν ξεκλειδώσουν τα αποτελέσματα.

### Μεταβλητές περιβάλλοντος

| Πού | Μεταβλητή | Χρήση |
|---|---|---|
| Render | `DATABASE_URL` | Σύνδεση με το Neon |
| Render | `ADMIN_PASSWORD` | Ο κωδικός του διαχειριστή |
| Render | `SESSION_SECRET` | Υπογραφή των tokens συνεδρίας του διαχειριστή |
| Render | `WEB_ORIGIN` | Η διεύθυνση του Vercel, για CORS |
| Vercel | `VITE_SERVER_URL` | Η διεύθυνση του server στο Render |

## 4. Δεδομένα

```sql
quizzes   (id, title, time_limit_sec INT 5..300 DEFAULT 30, created_at, updated_at)
questions (id, quiz_id → quizzes ON DELETE CASCADE, position INT, text,
           options TEXT[] 2..4, correct_index INT, time_limit_sec INT NULL 5..300)
games     (id, quiz_id → quizzes ON DELETE SET NULL, quiz_title, code CHAR(6),
           questions JSONB,            -- αντίγραφο των ερωτήσεων τη στιγμή που ξεκίνησε το παιχνίδι
           status,                     -- lobby | question_open | question_closed | revealing | finished | cancelled
           current_index INT NULL, question_ends_at TIMESTAMPTZ NULL,
           reveal_step INT NULL, created_at, finished_at NULL)
teams     (id, game_id → games ON DELETE CASCADE, name, token UNIQUE, joined_at, removed_at NULL)
answers   (game_id, team_id, question_index INT, choice INT, updated_at,
           PRIMARY KEY (team_id, question_index))
```

- **Αντίγραφο ερωτήσεων.** Το παιχνίδι κρατά δικό του αντίγραφο (`games.questions`). Αν ο
  διαχειριστής αλλάξει ή σβήσει το κουίζ, τα τρέχοντα και τα παλιά παιχνίδια δεν επηρεάζονται.
- **Κωδικός παιχνιδιού.** Τυχαίος εξαψήφιος, μοναδικός ανάμεσα σε παιχνίδια που δεν έχουν
  τελειώσει ή ακυρωθεί.
- **Όνομα ομάδας.** 1–30 χαρακτήρες μετά το trim, μοναδικό μέσα στο παιχνίδι χωρίς διάκριση
  πεζών-κεφαλαίων. Οι ομάδες που αφαιρέθηκαν (`removed_at`) δεν μετράνε πουθενά.
- **Απάντηση.** Μία γραμμή ανά ομάδα και ερώτηση. Κάθε αλλαγή ενημερώνει την ίδια γραμμή. Γράφεται
  στη βάση τη στιγμή που φτάνει.
- **Βαθμολογία.** Υπολογίζεται από τα `answers` και το `games.questions`. Δεν αποθηκεύεται
  ξεχωριστά.
- **Μεταπτώσεις βάσης.** Αρχεία SQL στο `server/migrations/` που εκτελούνται με τη σειρά κατά την
  εκκίνηση του server.

## 5. Ροή και καταστάσεις παιχνιδιού

```
lobby ──Έναρξη──▶ question_open ──λήξη χρόνου / Κλείσιμο τώρα──▶ question_closed
                        ▲                                              │
                        └──────────────── Επόμενη ─────────────────────┤
                                                                       │ (μετά την τελευταία)
                                                     Αποτελέσματα ─────▼
                                     revealing (reveal_step 0 … Q+T−1) ──▶ finished
```

- **Έναρξη / Επόμενη:** `current_index` += 1, `question_ends_at = now + χρόνος ερώτησης`.
  Ο server προγραμματίζει το κλείσιμο. Όλοι λαμβάνουν την ερώτηση και το `endsAt` μαζί με το
  τρέχον ρολόι του server, ώστε τα χρονόμετρα στις οθόνες να συγχρονίζονται.
- **Απάντηση:** γίνεται δεκτή μόνο αν η ερώτηση είναι ανοιχτή και `now ≤ question_ends_at + 500 ms`
  (περιθώριο για την καθυστέρηση του δικτύου). Αλλιώς ο αρχηγός παίρνει «Ο χρόνος έληξε».
- **Κλείσιμο:** στη λήξη ή με «Κλείσιμο τώρα». Η κατάσταση γίνεται `question_closed`.
- **Αποτελέσματα:** διαθέσιμα μόνο όταν έχει κλείσει η τελευταία ερώτηση. Η κατάσταση γίνεται
  `revealing` με `reveal_step = 0`. Κάθε πάτημα του παρουσιαστή αυξάνει το `reveal_step`:
  - βήματα `0 … Q−1`: η ερώτηση `i` με τη σωστή της απάντηση,
  - βήματα `Q … Q+T−1`: μία ομάδα κάθε φορά, από την τελευταία θέση προς την πρώτη
    (Q = ερωτήσεις, T = ενεργές ομάδες),
  - μόλις εμφανιστεί η 1η θέση, η κατάσταση γίνεται `finished` και τα κινητά ξεκλειδώνουν
    (αν δεν υπάρχει καμία ομάδα, το `finished` έρχεται αμέσως μετά την τελευταία ερώτηση).
- **Αφαίρεση ομάδας:** ο παρουσιαστής μπορεί να αφαιρέσει ομάδα σε οποιαδήποτε κατάσταση πριν
  από το `revealing`. Το κινητό της δείχνει «Η ομάδα σας αφαιρέθηκε από τον παρουσιαστή».
- **Ακύρωση:** από τη διαχείριση, για παιχνίδι που δεν έχει τελειώσει. Η κατάσταση γίνεται `cancelled`.
- **Επανεκκίνηση server:** κατά την εκκίνηση, κάθε παιχνίδι σε `question_open` ξαναπρογραμματίζει
  το κλείσιμό του (ή κλείνει αμέσως αν ο χρόνος έχει περάσει). Όλα τα υπόλοιπα διαβάζονται από τη
  βάση, οπότε το παιχνίδι συνεχίζει.

## 6. Επικοινωνία

### REST (διαχείριση, με `Authorization: Bearer <admin token>`)

- `POST /api/admin/login {password}` → token υπογεγραμμένο με HMAC, λήξη σε 12 ώρες.
- `GET/POST /api/quizzes`, `GET/PUT/DELETE /api/quizzes/:id`: το κουίζ μαζί με τις ερωτήσεις
  του. Το PUT αντικαθιστά όλη τη λίστα ερωτήσεων.
- `POST /api/quizzes/:id/games` → νέο παιχνίδι σε `lobby` (απαιτεί ≥ 1 ερώτηση).
- `GET /api/games?status=active|past`, `POST /api/games/:id/cancel`.
- `GET /api/games/:id/results`: η τελική κατάταξη ενός παιχνιδιού.
- `GET /health`: για έλεγχο ότι ο server είναι ξύπνιος.

### Socket.IO

| Από | Μήνυμα | Περιεχόμενο / απάντηση |
|---|---|---|
| Αρχηγός | `team:join` | `{code, name}` → `{token}` ή σφάλμα |
| Αρχηγός | `team:resume` | `{token}` → τρέχουσα κατάσταση ή σφάλμα |
| Αρχηγός | `team:answer` | `{questionIndex, choice}` → ok ή σφάλμα |
| Παρουσιαστής | `host:watch` | `{gameId}` (ο σύνδεσμος socket φέρει το admin token) |
| Παρουσιαστής | `host:start`, `host:next`, `host:close`, `host:results`, `host:reveal-next` | ελέγχουν τη ροή |
| Παρουσιαστής | `host:remove-team` | `{teamId}` |
| Server | `game:state` | στιγμιότυπο προσαρμοσμένο στον ρόλο (βλ. παρακάτω) |

Ο server στέλνει πλήρες στιγμιότυπο `game:state` σε κάθε αλλαγή, όχι επιμέρους διαφορές. Έτσι
η επανασύνδεση και ο συγχρονισμός είναι απλοί.

- **Στιγμιότυπο παρουσιαστή:** κατάσταση, κωδικός, ομάδες (ονόματα), τρέχουσα ερώτηση με
  επιλογές, `endsAt`, `serverNow`, «απάντησαν Χ από Υ». Στο `revealing`, μόνο ό,τι έχει
  αποκαλυφθεί ως το τρέχον βήμα.
- **Στιγμιότυπο αρχηγού:** κατάσταση, όνομα ομάδας, τρέχουσα ερώτηση με επιλογές, `endsAt`,
  `serverNow`, η τρέχουσα επιλογή της ομάδας. Στο `revealing`, μόνο «κοιτάξτε την οθόνη». Στο
  `finished`: κατάταξη, θέση και πόντοι της ομάδας, και για κάθε ερώτηση η επιλογή της ομάδας και
  η σωστή.

## 7. Οθόνες

Ύφος τηλεοπτικού στούντιο (βαθύ μπλε, χρυσό), ίδιο με το πρώτο κουίζ. Όλα τα κείμενα στα ελληνικά.

- **`/admin`:** σύνδεση με κωδικό. Λίστα κουίζ. Επεξεργαστής κουίζ: τίτλος, χρόνος, ερωτήσεις
  (προσθήκη, αλλαγή, μετακίνηση πάνω/κάτω, διαγραφή, προαιρετικός χρόνος ανά ερώτηση). Έλεγχος
  πριν την αποθήκευση: κείμενο ερώτησης, ≥ 2 μη κενές επιλογές, σωστή απάντηση επιλεγμένη.
  Κουμπί «Νέο παιχνίδι». Λίστα ενεργών παιχνιδιών (Συνέχεια, Ακύρωση) και παλιών (τελική κατάταξη).
- **`/host/:gameId`:** για προβολέα, με κουμπί πλήρους οθόνης. Τα στοιχεία ελέγχου είναι σε
  διακριτική μπάρα στο κάτω μέρος.
  - Αναμονή: μεγάλος κωδικός, QR code, η διεύθυνση για πληκτρολόγηση, οι ομάδες καθώς μπαίνουν
    (με αφαίρεση).
  - Ερώτηση: αριθμός ερώτησης, κείμενο, επιλογές Α–Δ, μεγάλο κυκλικό χρονόμετρο,
    «Απάντησαν Χ από Υ».
  - Αποτελέσματα: μία ερώτηση με τη σωστή απάντηση ανά βήμα, μετά η κατάταξη που χτίζεται από
    κάτω προς τα πάνω, με την 1η θέση να εμφανίζεται τελευταία και ξεχωριστά.
- **`/play`:** για κινητό. Φόρμα κωδικού (προσυμπληρωμένος από το QR code) και ονόματος ομάδας.
  Αναμονή. Ερώτηση με μεγάλα κουμπιά Α–Δ, χρονόμετρο, φωτισμένη επιλογή και «Μπορείτε να την
  αλλάξετε ως τη λήξη». Μετά τη λήξη: «Η απάντησή σας καταχωρήθηκε» ή «Δεν απαντήσατε». Στα
  αποτελέσματα: «Κοιτάξτε την κεντρική οθόνη». Στο τέλος: θέση, πόντοι, κατάταξη, οι απαντήσεις
  της ομάδας με τη σωστή δίπλα.

## 8. Σφάλματα

| Περίπτωση | Τι βλέπει ο χρήστης |
|---|---|
| Λάθος κωδικός παιχνιδιού | «Δεν βρέθηκε παιχνίδι με αυτόν τον κωδικό.» |
| Όνομα που υπάρχει | «Υπάρχει ήδη ομάδα με αυτό το όνομα.» |
| Είσοδος σε παιχνίδι στα αποτελέσματα ή τελειωμένο | «Το παιχνίδι έχει ολοκληρωθεί.» |
| Απάντηση μετά τη λήξη | «Ο χρόνος έληξε.» |
| Server που ξυπνάει ή χαμένη σύνδεση | «Σύνδεση με τον server…» με αυτόματες επαναλήψεις. Μετά την επανασύνδεση, `team:resume`. |
| Άκυρο ή ληγμένο token ομάδας | Επιστροφή στη φόρμα εισόδου. |
| Λάθος κωδικός διαχειριστή | «Λάθος κωδικός.» |
| Ληγμένη συνεδρία διαχειριστή | Επιστροφή στη σύνδεση. |

Όλα τα δεδομένα που φτάνουν στον server ελέγχονται με σχήματα (zod) πριν χρησιμοποιηθούν.

## 9. Δημοσίευση

1. Αποθετήριο στο GitHub με τον κώδικα.
2. Neon: νέο έργο και βάση. Η σύνδεση πάει στο `DATABASE_URL` του Render.
3. Render: web service από τον φάκελο `server/`, με τις μεταβλητές της §3.
4. Vercel: έργο από τον φάκελο `web/`, με `VITE_SERVER_URL` και κανόνα που στέλνει όλες τις
   διαδρομές στο `index.html`.
5. Κάθε push στο `main` ανεβάζει αυτόματα και τα δύο.

Στο δωρεάν πλάνο του Render ο server κοιμάται μετά από περίπου 15 λεπτά χωρίς κίνηση. Η σελίδα
διαχείρισης καλεί το `/health` μόλις ανοίξει, ώστε να τον ξυπνήσει πριν από το παιχνίδι.

**Προαπαιτούμενα:** Node.js (LTS) στον υπολογιστή, λογαριασμός GitHub, λογαριασμοί Vercel, Render
και Neon.

## 10. Έλεγχος

- **Μονάδες (vitest):** βαθμολογία, ισοβαθμίες, σειρά αποκάλυψης, μεταπτώσεις καταστάσεων, όρια
  χρόνου με το περιθώριο, αλλαγή απάντησης, ότι το στιγμιότυπο αρχηγού δεν περιέχει ποτέ σωστές
  απαντήσεις πριν από το `finished`.
- **Ολοκλήρωση:** ο server με πραγματική Postgres (branch του Neon για τεστ) και πελάτες
  `socket.io-client`. Ένα πλήρες παιχνίδι με 30 ομάδες, αλλαγές απαντήσεων, μια αποσύνδεση και
  επανασύνδεση, μια επανεκκίνηση server στη μέση ερώτησης.
- **Χειροκίνητα:** μια δοκιμαστική παρτίδα στον browser με την οθόνη παρουσιαστή και μερικά
  κινητά, στις διευθύνσεις του Vercel και του Render.

## 11. Εκτός εμβέλειας

Εικόνες ή ήχος στις ερωτήσεις, ερωτήσεις ανοιχτού κειμένου, πολλοί διαχειριστές με λογαριασμούς,
μπόνους ταχύτητας, βοήθειες, αλλαγή κουίζ κατά τη διάρκεια παιχνιδιού, εξαγωγή αποτελεσμάτων σε
αρχείο.
